# Changelog

## 2.0.0

Correctness, privacy and scale. The storage format changed; existing history is
migrated automatically on first load, and old backups still restore.

### Fixed

- **The privacy claim is now true.** JSZip was loaded from cdnjs on every visit,
  so a third party saw every visitor and a compromised CDN could have read your
  Instagram data. It is bundled, there is no `integrity` gap because there is no
  request, and a strict CSP with `connect-src 'none'` makes "talks to nobody"
  something you can verify in DevTools rather than something you have to believe.
- **HTML exports produced phantom followers.** Any `instagram.com/<anything>`
  substring counted, so navigation links, post URLs and reel URLs were parsed as
  accounts. Only real profile anchors count now.
- **History outgrew localStorage.** Every snapshot stored the full username list
  again, roughly 150-200 KB at 3,000 followers, which exhausted the ~5 MB quota
  after a few months of weekly uploads - and the failure was silent. Usernames are
  interned once and snapshots hold integer ids, each extra snapshot now costs
  under a third of what it did, and a full quota offers to drop the oldest
  snapshots instead of losing your upload.
- **Follow dates went missing.** Only the latest two snapshots were searched for a
  timestamp, so "sort by newest" put anyone seen earlier at the bottom. First-seen
  dates are kept permanently.
- **Typing in search redrew everything,** tab bar and SVG chart included, on every
  keystroke. Search is debounced, the list renders at most 200 rows at a time, and
  the chart is only redrawn when the snapshots change.
- **Acting on a row threw keyboard focus to the top of the page.** Rows are patched
  in place, and focus moves to the neighbouring row when one disappears.
- **Parse failures were swallowed** with one generic message. The real error is
  logged and the message now names what was found and what was missing.
- Single-character usernames are no longer rejected.

### Added

- **Count check.** Tell it the follower count on your profile and it warns when
  the export does not match - the symptom of picking a date range other than
  All time, which is the most common cause of wrong results.
- **Timeline.** A dated log of every follow and unfollow across all snapshots,
  rather than only a diff between two.
- **Boomerang list.** Accounts that followed you and then unfollowed - the
  follow-for-follow pattern.
- Five more lists read from the export: recently unfollowed, blocked, restricted,
  close friends, and follow requests received. Recently unfollowed means the
  Unfollowed-you data is useful on the very first upload.
- **Bulk actions.** Select all filtered rows and hide or tick them off at once.
- **Real exports.** A proper quoted CSV download with the list, follow date, status
  and profile URL, and a backup `.json` file download with restore from file.
  Nothing depends on the deprecated `document.execCommand`.
- **Snapshot manager.** Label snapshots, and delete a bad one instead of letting it
  poison the chart forever.
- **Storage meter** showing how much of the browser's limit is in use.
- **Installable and offline** via a web manifest and a service worker.
- **Parsing runs in a Web Worker** with a progress bar, falling back to the main
  thread when a worker cannot start.
- Proper `tablist` semantics with arrow-key navigation, and hide/tick on every list.
- Favicon, social card, and a description.

### Changed

- Source split into tested ES modules under `src/`, with `index.html` generated by
  `build.js`. 74 tests run on Node 22 in GitHub Actions, which also fails if the
  committed build is stale.
